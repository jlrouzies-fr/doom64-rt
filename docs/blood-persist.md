# Persistent blood

`Doom64-Retribution/d64r-blood-persist.pk3` — generated by
`tools/gen_blood_persist.py --apply`, A/B'd with `tools/ab-blood.cmd`.

## The one-second lifetime was never a renderer setting

BLUD splats vanished about a second after they landed. Nothing in RTGL1 or in
any `rt_*` cvar did that. It is authored in the Retribution WAD's own
`DECORATE` lump (`D64RTR_v15.WAD`, line 1951):

```
ACTOR 64Blood : Blood REPLACES Blood
    Spawn:
        BLUD D 0
        BLUD D 0 A_SpawnItemEx("64Blood2",  5,  5, ...)
        BLUD D 0 A_SpawnItemEx("64Blood2", -5, -5, ...)
        BLUD D 8
        BLUD CBA 8
        Stop                       <- 32 tics, ~0.9 s
```

Three actors are involved: `64Blood` (the main splat, and the one that
`REPLACES Blood`), `64Blood2` (the two satellites it throws), and
`64InvisiBlood` (the MAP00 target-range dummy's Add-blended blood).

The four frames **grow**, they do not shrink — `BLUDD0` is 16×4, `BLUDA0` is
16×12 — so the sequence already ends on the biggest splat. Persisting it is a
matter of holding that frame instead of reaching `Stop`.

## Two halves, in two languages, on purpose

**Lifetime — `DECORATE`.** It has to be. `64Blood` is a DECORATE class, ZScript
is parsed *before* DECORATE, and so no ZScript class can inherit from it. A
DECORATE actor that `replaces 64Blood` is the only way to touch those states.
The pk3 ships `RTBloodPersist` / `RTBloodPersist2` / `RTBloodPersistInvis`,
each ending on `BLUD A -1` — infinite tics. Gravity lives in `Actor::Tick`, not
in the state machine, so the splat still falls and settles on the floor; only
the animation stops.

The replacement chain resolves `Blood → 64Blood → RTBloodPersist`
(`GetReplacement` recurses), and the pk3 loads after `D64RTR_v15.WAD` in
`launch-retribution-rt.cmd`.

**Randomization and the cap — `ZSCRIPT`.** DECORATE cannot read a cvar and
cannot hold a list of every splat in the level. `RTBloodPersistHandler`
(registered by the pk3's `MAPINFO`) does both from `WorldThingSpawned`.

## Randomization

Permanent blood is exactly the case where identical sprites stop reading as
blood and start reading as a repeated stamp. Three things vary:

- **count** — the satellites were at a fixed `(+5,+5)` and `(-5,-5)`. Now 1–3
  of them at `random(-14,14)` offsets, gated by `A_Jump`. Mean 1.9375, so the
  sprite count per hit is essentially unchanged.
- **size** — `Scale *= 1 ± rt_gore_scale_var`, floored at 0.5.
- **mirror** — `bXFLIP` at random. A UV flip, no extra geometry.
- **roll** — `bROLLSPRITE` + random `Roll`, off by default (see below).

## Cvars

All `noarchive`, all pinned explicitly in `launch-retribution-rt.cmd` and in
every `ab-blood.cmd` arm.

| cvar | default | what it does |
|---|---|---|
| `rt_gore_life` | `0` | tics before a splat is destroyed. `0` = forever. `32` reproduces stock Retribution — this is the *only* way to get an "off" arm, since DECORATE cannot read a cvar. |
| `rt_gore_max` | `1500` | hard cap on live splats, oldest destroyed first. `0` = unlimited. |
| `rt_gore_scale_var` | `0.35` | ± size jitter. `0` = every splat identical. |
| `rt_gore_roll` | `false` | random billboard roll. |

**Do not confuse `rt_gore_*` with `rt_blood_tint_*`.** The latter is the blood
*liquid surface* (see `docs/rt-water.md`) and has nothing to do with splats.
That collision is why these are `rt_gore_` and not `rt_blood_`.

## Why the cap exists

Every hit leaves 1–3 permanent sprite actors. Offscreen ones cost only a
thinker tick — `hw_sprites` never processes a sprite in an unseen subsector, so
RTGL1 never sees them — but an unbounded queue over a long map is still a queue
nobody bounded. 1500 recycles the oldest, which at that count is essentially
never in view. `ab-blood.cmd tight` (cap 300) makes the recycle pop visible so
the number can be judged rather than guessed; `ab-blood.cmd uncapped` is the
honest perf read.

## Open question

`rt_gore_roll` is off by default because it is the one part not verified in
game. `ROLLSPRITE` is applied in `HWSprite::Process`, upstream of the RT
upload, so RTGL1 *should* receive already-rotated geometry — but if the splats
render unrotated, or z-fight the floor once tilted, roll stays off and comes
out. `ab-blood.cmd roll` is that test, and nothing else changes in that arm.
